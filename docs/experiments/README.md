# Експерименти

Відтворювані заміри для експериментальної частини магістерської роботи.

## Оцінка пошуку — `search_eval.py`

Порівнює три пошуки по історії листування на реальному архіві:

| Пошук | Як працює |
|---|---|
| Повнотекстовий | PostgreSQL `tsvector`, конфігурація `simple`, GIN-індекс |
| Семантичний | вектори `bge-m3` (Ollama, локально), косинусна схожість |
| Гібридний | обидва списки top-30, злиті методом Reciprocal Rank Fusion (k = 60) |

**Методика.** Кожен запит у `queries.local.json` має регулярний вираз, що визначає
релевантне повідомлення, і тип:
- `literal` — слова запиту є в повідомленні;
- `paraphrase` — сенс той самий, а слова інші.

Для кожного запиту скрипт бере top-10 результатів кожного пошуку і рахує:
- **Hit@k** — частку запитів, у яких релевантне повідомлення є серед перших k результатів;
- **MRR** — середнє 1/позиція першого релевантного результату;
- **медіану часу відповіді**.

Перед замірами по одному запиту на кожен пошук іде на «прогрів», щоб не міряти холодний старт.

**Запуск** (застосунок має працювати):

```
set MH_EMAIL=you@example.com
set MH_PASSWORD=...
python search_eval.py --api http://localhost:8079
```

Звіт зберігається в `results/search-eval-<дата>.md`. У звіті є лише запити й метрики, тексту повідомлень там немає.

`queries.local.json` не потрапляє в git, бо його шаблони — фрагменти приватного листування.
Формат файлу показано в `queries.example.json`.

## Результат від 2026-10-31

Архів: 2 339 повідомлень. Запитів: 30 (15 дослівних, 15 перефразованих).

| Пошук | Hit@1 | Hit@3 | MRR | Медіана, мс |
|---|---|---|---|---|
| Повнотекстовий | 43% | 43% | 0.43 | 16 |
| Семантичний (bge-m3) | 73% | 90% | 0.82 | 50 |
| **Гібридний (RRF)** | **87%** | **93%** | **0.90** | 61 |

- На **дослівних** запитах гібридний пошук дає 100% Hit@1. Повнотекстовий дає 87%: йому
  заважають словоформи, бо конфігурація `simple` не має стемінгу для української. Семантичний
  дає 73%: правильне повідомлення часто опиняється другим чи третім.
- На **перефразованих** запитах повнотекстовий пошук безсилий (0%), а гібридний тримає рівень
  семантичного (73%).
- Отже, злиття не погіршує жоден із випадків: на кожному типі запитів гібрид не гірший за
  кращий з двох окремих пошуків.

**Обмеження.** Набір невеликий (30 запитів), і запити складав розробник, який знає архів. Ці
цифри показують відносну різницю між методами на одних і тих самих даних, а не абсолютну
якість.
